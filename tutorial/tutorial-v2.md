# Domi 使用教程

编辑时间：2026 年 8 月

适用版本：Domi `0.16.x`（Pi-only Runtime）



## 写在开始之前（推荐看）

> 这份教程更像是一份带观点的“说明书”，而不是传统意义上的知识。我们希望帮你建立一套真正用得起来的 Agent 工作方式：解决真实的问题，在真实的环境里不断迭代。如果你已经能用 Agent 解决 2 个以上的实际问题，那你已经拥有了真实环境；接下来要思考的是如何循环和迭代——下次处理同类问题时多说一句话、多加一个限定条件，或者把重复的流程沉淀成规则。

**核心心法：**

- **Agent 不难**。真正难的是被错误认知吓退：总觉得它很难、很神秘。实际上 Agent 的运行方式各家大同小异，差别只在于你给它的上下文质量和反馈环境。
- **上下文比模型重要**。给 Agent 一份完整、明确、经过筛选的上下文，它的表现会远超一个模糊指令。
- **按需索取**。这份说明书很长，你不必一次看完。遇到某个功能不知道怎么用的时候，回来翻对应章节即可。

接下来就是“说明书”的部分了。



## 快速开始（包含配置）

### 下载和安装

Domi 是本地优先的 Personal Coding Workbench，多模型 Chat 与通用 Agent 工作流放在同一个桌面客户端里。Domi 使用独立的本地应用身份和数据目录（正式版 `~/.domi/`，开发版 `~/.domi-dev/`），不连接 Proma 官方更新通道。你可以从源码构建；如果获得适用于当前平台的二进制构建，请手动安装和更新。

### 必要的依赖安装

Work 模式依赖本机基础环境：

- **Git**：版本管理与代码协作的基础。
- **Node.js / Bun**：绝大多数工具链、MCP Server、Skills 脚本的运行环境。
- **可用的 Shell**：Windows 上推荐 PowerShell 或 Git Bash。

首次启动时 Domi 会做环境检查，跟随向导完成缺失依赖的安装即可。Windows 用户注意：安装 Git / Node.js 时，务必勾选安装流程内的 `Add to Path`。

### 配置 AI 供应商

**AI 供应商概念：就是各家 AI 厂商提供的大模型 API 配置入口。Domi 支持几乎全部主流厂商，以及 OpenAI 兼容、Anthropic 兼容、Google Gemini 等格式。**

以 DeepSeek 为例：

1. 打开 Domi 左下角的设置，进入「渠道」。
2. 点击右上角「添加渠道」，供应商类型选择 DeepSeek（或 Kimi、GLM、MiniMax、OpenAI、Anthropic 等）。
3. 填写 Base URL 与 API Key。Base URL 通常不需要手动加 `/v1` 或 `/v1/xxx`，Domi 会自动处理。
4. 通过「从供应商获取」拉取模型列表，勾选你实际会用到的模型（不必全选）。
5. 点击顶部「创建渠道」保存。

补充说明：

- **Work 模式**统一使用 Pi Agent Runtime，任意已启用的渠道（包括 Anthropic / Claude 模型、DeepSeek、Kimi、GLM、通义千问、豆包、MiniMax 等）都可以作为 Agent 供应商；支持 ChatGPT 订阅（Codex OAuth）。
- Chat 模式可以使用 OpenAI、Anthropic、Google 或 OpenAI 兼容协议的渠道。
- 如需记忆、联网搜索、飞书 / 钉钉 / 微信桥接，在设置页对应 Tab 中继续配置。

### Work 和 Chat 模式的区别

**Chat 模式**：适合问答、解释、翻译、润色、轻量讨论。它能读附件、联网搜索、用记忆工具，但本质是“回答你的问题”。

**Work 模式**：Agent（代理）= 大模型 + 工具能力。它可以读写文件、执行 Shell、跑测试、管理 Git、调用 MCP 与 Skills，把一个多步骤任务从头做到尾——包括把结果写成文档、改完代码并验证。**需要动手和交付结果时用 Work，只需要回答时用 Chat。**

Work 模式提供独立的 **Execution Policy**（Controlled / Autonomous / Full Access）与 **Workflow**（Direct / Plan First），配合工具门禁保证每一步操作可控、可审批、可审计。新会话默认使用 Controlled + Direct。

第一次使用 Work 时，如果不知道某个功能怎么配、某个流程怎么拆，可以直接向 Domi Agent 表达你的需求或不满——Domi 内置的 `domi-coach` Skill 会在合适的时机主动介入，帮你把摩擦点转成更顺手的使用方式或知识维护动作。



## 文件设计（如何组织好给 Agent 的文件）

Domi 的右侧是文件区域。为什么需要文件？因为很多任务本质是处理文件——读、改、生成。**读写文件的能力，是这一轮 AI Agent 的核心。**

文件本身就是上下文，而且通常是更好的上下文：它们经过整理、筛选和校验，是经过组织的信息。右侧显示的文件或文件夹，Agent 都有能力主动访问，但不保证每次都访问。如果你明确知道某件事依赖某个文件，就用 `@` 引用它，或用自然语言明确说明。

### 插播：完整、明确、清晰的上下文

人类之间交流时，很多信息靠环境补全，比如“帮我把那个下周的报表做一下给小李”——这句话在办公室里能懂，但直接给 Agent 就是糟糕的语义。好的 Agent 提示词需要把上下文说完整，例如：

> 在当前项目根目录下有个 `@xx.xlsx` 文档，这是本月销售报表，核心产品是 a、b、c；成本在另一个 `@yy.xlsx` 文档，成本项和销售项的对照关系在 sheet2。请先访问这两个文档，帮我整理销售毛利率，结果写到 `@xx.xlsx` 的 sheet1。格式参照文档里的说明；数据有缺漏的地方明确指出来，我来补充；任何不确定的地方停下来跟我确认；完成后给我一份分析方法的总结。

是的，就是需要长到有点厌烦的程度，这才是好提示词。如果打字太累，可以用 Domi 的语音输入（豆包流式语音识别，全局快捷键 Ctrl + `）加快节奏，口语化表达也没关系。

更进一步：如果这个流程经常做，把它沉淀成 Skills（见下文），下次一句话触发。

### 什么是好的会话

**不要长时间在同一个 Agent 会话里持续交互几十次甚至几百次。** 一个会话最好只处理一个简短、聚焦的任务。原因：

- 上下文越长越脏，每次请求消耗的 Tokens 更多、成本更高；
- 上下文越长，模型响应越慢；
- 上下文越长，模型表现越差，对提示词质量的要求反而更高。

**最佳实践：**

- 一个数据分析任务做完，就是一个会话。下次要做不相关的事，新建会话（左侧列表项目目录右侧的加号）。
- 编程任务，一个会话对应一个小功能迭代或一次 Bug 修复，而不是整个项目开发。
- 但如果同一件事隔天继续做（比如“原始数据更新了，按上次方案重新分析”），继续在旧会话里简短表达一次更好，不必每次从零描述。

### 文件设计——三个层级的边界

Domi 把文件分为三个层级，理解边界能让 Agent 的上下文更干净、输出更快更稳：

**会话文件**：只服务当前这一次任务。适合临时输入、计划、阶段性设计和本次任务的产物。直接把文件拖到输入框，默认加入当前会话。

**项目根目录**：一个项目长期工作的主文件夹。新建空白项目时，Domi 提供托管的项目目录（`workspace-files/`）；选择“从本地文件夹创建项目”时，所选原始文件夹就是项目根目录，项目内所有会话都可以直接读写它。适合放代码库、长期参考资料、跨会话复用的产物和最终交付物。注意：本地项目根目录的改动会直接写入你的原始文件，它不是临时目录。

**附加目录和文件**：额外授权给当前会话或整个项目的既有资料。适合参考库、素材库、Obsidian 仓库等不想复制进项目根目录的内容。附加目录不是项目根目录，也不会自动成为 Agent 的默认工作目录。

### 文件设计进阶——主动设计更符合语义的文件

会话工作台和项目根目录下各有一层 `.context/`，但用途不同：

- **会话级 `.context/`**：本次任务的 Todo、Plan、临时笔记等。
- **项目级 `.context/`**：跨会话共享的 Note、设计、进度和项目级知识。

如果任务很长、一次会话难以完成，可以让 Agent 在项目根目录的 `.context/` 中维护设计、进度和踩坑记录。之后开新会话时，告诉 Agent 继续阅读这份项目级 Context；不确定的部分还可以用 `&` 引用相关会话。这样就能让大型任务在多个会话中持续迭代。

结构化资料也可以放在项目根目录的专用文件夹中，例如用 JSONL 维护面试、简历或项目资料库，然后在新会话里继续查询、对比和迭代。

最后注意：Skills、MCP、Domi 工作区的 AGENTS.md 与 Memory 由 Domi 工作区统一管理。当前受信 Session Target 项目根的 AGENTS.md 可作为项目指令显式生效，但不会从祖先目录或附加目录自动发现配置；需要接入 Skills / MCP 时仍请在 Domi 管理界面显式配置。



## Skills 和 MCP

Skills 不是复杂概念，创建也基本不需要人写代码——你提供一个初始想法，Agent 逐步跟你确认，就可以完成一个 Skills。

**Skills 的核心是更好的提示词**：用更高质量的提示词驱动某些流程，使其达到某种稳定的质量。这就是它的意义。

### 关于 Skills 的认知

Skills（技能）是你对工作技能的核心认知，用语言层级化地表达出来。注意：

- 一个行业或场景不只有一种 Skills，你可以完全用自然语言创建自己的 Skills。
- 互联网上已有大量 Skills，但质量参差不齐。推荐先通过对话查找，再测试甄别。
- Domi 支持 Skills 开关：Work 模式左下角展示当前工作区已开启的 Skills 和 MCP，点击即可管理。

**换个视角想 Skills**：如何把你的工作交给一个新人来做？流程是什么、核心判断是什么、哪些判断是你经验结晶？把这些告诉 Domi Agent，让它帮你变成 Skills，并持续优化——Skills 不是一成不变的。

这就是用自然语言对你的工作流程编程：知识和 Know How 的运行核心不再是 CPU，而是大模型 Agent。

### 如何创建 Skills

1. **从会话沉淀**：在某个会话下完成一项工作，觉得“做得还不错，下次也要用”，就让 Agent 把刚才的工作抽象成一个 Skills。
2. **从流程表述**：直接在 Work 模式下描述你的工作流，让 Agent 把它转换成 Skills。之后一句话就能触发整个流程，例如“帮我处理最新的 PR”。
3. **注意责任**：Skills 是反复运行的比较严格的提示词。创建成功后要检查它具体怎么写，是否真的符合你的要求，不要盲信一次生成的结果。

创建成功后会收到通知，也可以在左下角 Skills 管理区域查看。

### 如何用别人的 Skills

Domi 内置了 `find-skills` Skill。你可以在 Work 模式下新开对话，直接输入 Skills 的公开网页地址，或用自然语言描述，比如“帮我找一些可以提高我做生物学领域研究的 Skills”。Agent 会帮你找到候选，你阅读后决定是否安装——只需自然语言说“帮我把 xxx skills 安装到本地”即可。

### 如何共享你的 Skills

- 通过数据迁移方式导出 Skills，打包发给别人；对方收到文件后双击即可导入。
- 或者直接让 Domi Agent 把 Skills 压缩成压缩包，对方解压后安装到自己的工作区。

### 在不同工作区之间复制 Skills

Skills 和 MCP 都是分工作区的，这是为了保持上下文的干净。需要跨工作区复制时，让 Domi Agent 帮你复制，或在设置里手动迁移。

### Skills 迷思

不推荐安装太多 Skills：装得越多，语义越模糊，效果反而下降。市面上很多 Skills 只是“为了存在而存在”，未必比得上你跟 Agent 一起沉淀、经过实际检验的那一个。**创建 Skills 的难度并不比发一条微博更高**，真正要的是谨慎和真实：现在就可以跟 Domi Agent 一起创建一条你真心关注、流程性、解决实际问题的 Skills。

### 关于 MCP

MCP（Model Context Protocol）是连接外部能力的标准协议。你可以完全跟 Agent 交互，让它帮你安装你需要的 MCP Server——比如飞书文档、Gmail、数据库等。Domi 的每个项目独立配置 MCP Server，支持 stdio / HTTP 传输，可按需启用或关闭。涉及授权的 MCP 通常需要你生成授权信息，跟着 Agent 引导完成即可。



## 关于自动任务

自动任务的场景其实一直存在，只是过去大家用 Agent 的时间太短，没把自己的用法迭代到自动化的程度。今天是真的到了。

Domi 内置了持久化的自动任务系统（Automation），适合无人值守、有稳定价值的场景——既包括长期反复的周期任务，也包括“未来某个时间点跑一次”或“跑有限几次就停”的延时任务。你可以在侧边栏的自动任务入口进入管理页面查看和编辑。

### 如何创建一个好的自动任务

最天然的场景是：**你刚跟 Agent 协作做完一件事，觉得做得不错、没出错，而且过段时间还要做。** 这就是最好的信号——在这个会话下继续跟 Agent 说，让它帮你创建一个这个流程的自动任务。

创建后建议：

- 先手动执行一次，确认任务可以稳定运行。
- 不满意就继续跟 Agent 交互，迭代提示词和频率。
- 好的自动任务不是“定时提醒你喝水”，而是有真实场景、可持续产生价值的任务（比如每天自动审计、定期汇总、发布后自动检查、竞品/价格跟踪）。

自动化任务支持完成后通过飞书推送，在手机上也能查看结果。



## 远程访问和使用

Domi 支持通过飞书 / Lark 机器人桥接远程使用，并已提供钉钉、微信桥接入口。用手机或群聊就可以触发本机 Agent 工作流。

- **飞书**：体验最好，支持流式卡片，还支持 CLI，可以打通飞书文档、会议、日程等能力。配置过程基本都是扫码完成。
- **钉钉 / 微信**：桥接入口已提供，适配能力持续完善中。

配置入口在设置页的远程机器人 Tab。只要电脑不进入睡眠模式，就可以在手机上给本机 Domi 指派任务，甚至让 Agent 完成后把研究内容发回你的邮箱或群聊。



## 如何更进一步

说明书部分接近尾声。**更进一步的一半是你要做的工作**：保持好奇心和真实能得到反馈的场景，每次跟 Agent 完成一次迭代后，想一想“下次它能做得更快更准吗？我要多说一句话、多加一个限定条件吗？”——更进一步的路往往就是这么简单。

**另一半是 Domi 正在做的**：

- Domi 会持续迭代 `domi-coach` Skill，在合适的场景主动帮你找到更顺手的使用方式。
- Proactive 方向：Domi 会在你授权的前提下，通过更多 Tokens 主动扫描你的本地交互记录，给出优化建议——可能是改善 Agent 的使用方式、推荐几个合适的 Skills、生成几个稳定运行的定时任务，甚至根据你长期的使用方式，在 Domi 内给你写一个更适合你工作的软件。

所有这一切的第一原则是：**解决真实的问题**，而不是追求“世界第一个 xxx”。



## 结语

Domi 还在飞快进化，这份说明书也会随迭代更新。

如果你想用好 Agent，记住三件事：

1. **做你喜欢做、你开心的事**——不是刷短视频和看小说，是能带来长期价值的事。
2. **这个世界从未如此平坦**——大胆一点、主动一点，不要被“一看 xx 就不行”的想法限制。Agent 就是这种基础设施和不被限制的产物。
3. **保持简单和健康**——即便你不想深入 AI 的世界，也要保护好我们的大脑。注意力本身就是评判健康与否的重要标准。
